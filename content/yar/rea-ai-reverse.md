看见别人软件里一个好用功能，想弄懂它怎么做的，再学着用到自己项目里。源码不在手里，网页聊天机器人又只能猜。这阵子圈子里常被提起的 REA，干的就是这件事。它给本机的 AI 助手接上一套本地工具，让助手把现成软件拆开看清内部怎么跑，再把发现和证据一起交回来。

官方仓库叫 morluto/rea，npm 包名 rea-agents，站点在 [rea.tools](https://rea.tools)。它是一个给 AI 助手用的本地工具插件，行业里常叫 MCP（可以把它理解成助手和本机工具之间的接线板）。装上之后，Cursor、Claude Code、Codex、Gemini CLI、Grok Build 这类本地助手，可以直接调用你电脑上的分析工具，去看已经编译好的程序文件，也去看用 Electron 技术壳做的桌面软件（Electron 就是很多桌面应用外面套的那层壳，比如 Notion 桌面版），以及网站行为。分析跑在你自己的机器上。助手会收到工具结果，模型提供商另有自己的数据政策，官网上写明了。

装起来不复杂。电脑上先装好较新的 Node，然后在终端跑下面这行。

```bash
npx rea-agents setup
```

选中你的助手，看一眼它打算改哪些配置，批准就行。流程会把插件接上，再装一份匹配的工作流指引，并备份旧配置。做完重启助手。官方给的示例提问大概是这样。

```txt
弄清 Notes 应用的搜索功能如何工作，展示证据，并为我的项目实现类似功能。
```

把 Notes 换成你手里的目标，把搜索换成你眼下好奇的那一段行为。问完之后，助手会顺着工具结果往下拆，尽量把关键步骤和引用交回来。你仍然要自己看懂返回来的限制和证据，它不会替你拍板能不能照做。

很多人会先问，一定要装 Hopper、Ghidra、IDA 这类专业反编译软件吗。拆很底层的原生程序时才需要其中之一。看网页和很多桌面 JS 应用，往往不需要。设置流程也可以在你批准后装 Hopper。Ghidra 和 IDA 则用你已经装好的那份。

官方案例里最好懂的，是 Notion 桌面端怎么把内容写进系统剪贴板。你在页面里点复制，页面先喊一声，中间有一层传话通道把请求送到后台，负责写入系统剪贴板的代码在后台那头。REA 顺着这条链找到传话通道（官方材料里叫 `notion:clipboard:write`），再跟到后台的处理函数。处理函数会检查发送方是不是 Notion 自己的页面，通过以后才把文本和 HTML 交给系统剪贴板。复制块时，HTML 里还会塞一个 ID，本地另存结构化内容，粘贴时按 ID 把块数据捞回来。你看见的是复制动作，底下是页面喊话、中间传话、发送方校验，再加上一套自己的块数据协议。

另一个案例更硬。DX-Ball 里有一段按位置算声像的函数。官方写他们沿着声音调用追到辅助函数，把不完整的伪代码补成 C，重建结果通过了 3205 个原始测试用例，还复现了编译后函数的全部 63 个字节。这类材料适合当成证据门槛来看。助手最后要拿出能对上机器码的东西，光讲故事不够。

谁适合装。你已经在用 Cursor 这类本地 AI 写东西，愿意给它接本地工具插件，手里又经常有想弄懂别人怎么实现的具体问题，REA 对得上。如果你只会在网页里跟聊天机器人说话，不想碰终端，这套东西暂时进不去，先看 Notion 和 DX-Ball 两个案例页，也能摸清它在解决什么问题。深度啃闭源原生程序，还得自己搞定专业反编译软件的授权。REA 是 MIT，但 IDA、Hopper、JEB 这些商用工具的许可证要你自己买，项目不附带密钥或破解途径。

它面向合法研究、教育、互操作和软件保存，只分析你拥有或获准检查的软件。写产品时拿来对照公开接口、学习桌面软件桥接、验证自己复现的算法，都在这条线里。

最后提一句安装来源。只从 morluto/rea、[rea.tools](https://rea.tools) 和 npm 上的 rea-agents 获取。名字像、说明文档抄过去的仓库，不能证明下载物是官方发布。更新也尽量走官方命令，或者再跑一遍 setup，重启助手。

已经在本地折腾助手的人，值得装一次试试。还在观望的人，先把两个官方案例页翻完，心里也会有数。
